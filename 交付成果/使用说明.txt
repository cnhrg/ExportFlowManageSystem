1. 打开方式
双击“代理出口业务流程图.html”，使用较新版本的 Chrome / Edge / Safari。

2. 三份主要交付
本轮产品原型更新：
“协议设计”下方新增“数据库设计”及“状态机设计”两个独立入口。
数据库设计按交易档案、资金账户流水、RBAC账号权限、系统配置四个Tab展示；各Tab首屏为ER图，随后为领域聚合、生命周期、不变量、跨域契约、操作审计和实体约束。
每个实体的ER字段增加“字段说明”列；下方逐实体字典同步展示字段、类型、键及字段说明，跨域实体标明引用归属。
交易档案仅保留trade_record、trade_snapshot、file_record三表。主表完整保存所有填写内容，必要文件各设路径列，非核心文件关联冗余存non_core_files_json。
trade_snapshot每次成功变更都追加完整before_record_json与after_record_json，记录操作人、原因、时间；审批新增事件快照，另存审批人、意见、时间及被审提交快照，不回填历史记录。
按每天单量很少的规模采用14张核心业务宽表：交易3张、资金4张、RBAC3张、系统4张。主体 / 商品 / 审批 / 规则等快照随业务宽表保存，JSON字段有schema、稳定子项ID和服务端校验，不拆大量关联表。
文件实际存文件存储，业务实体只存所用revision的路径；file_record为唯一文件记录表，同logical_file_id每次修改INSERT新行并递增revision，保留独立路径、元数据及全部历史，不设单证表或revision子表。
允许修改的文件每次保存产生新revision，旧文件不覆盖；审批 / 签署 / 申报 / 付款绑定当时路径，改用新路径须重审。并发基版冲突不覆盖当前版；回滚新增revision，文件逻辑删除或链接到期不清除历史revision。
状态机设计包含交易主状态、通用节点审核、合同、报关、税务、收款、付款、费用、账号、授权、配置发布、外部请求、审计导出及文件revision共14个子状态机。
主流程对齐表直接读取N01—N23名称、前置、分支及条件；明确预付/出口后付款互斥、N15已到账资金附加N13、N22四项前置汇合、N23更正逐级重审。
主流程原有批准佣金/垫资通用描述与资金设计V1（D承担两项费用、不垫资）分版本说明，不能混用规则或重复收费。

图示支持缩放、全图适配、阅读比例、源码查看和下载SVG/Mermaid；全部使用本地资源。

横向为业务阶段，纵向为 A/B/E/F、外部协作方及结案/异常。
四流以颜色区分；待确认节点有旗标，不再显示卡点标记或本机卡点操作卡。
可拖动空白画布平移，点击节点查看分类材料、输入输出及逐项校验规则。
节点同时列出所属流程、直接涉及的外部角色及交互事项；无直接外部交互的节点明确标明。
流程下拉框按操作指引步骤1—7筛选，流程8为另列的四流核对、结案与异常控制。
N06主归流程3并承接步骤1运输信息，N12主归流程5并包含步骤1主体资料和收货协作；
节点主分组不改变其跨步骤依赖。流程筛选隐藏组外节点，并保留付款分支、角色、四流及搜索筛选。
流程总览上方常驻流程1—8的八个时序图入口，也可从筛选后的时序图按钮或节点详情打开。
弹窗内“切换图示”可直接切换八份时序图和四份实体流转图，无需关闭弹窗。
默认时序图仅显示核验项目名称，不再显示N01-R01一类规则编号及长段判定、证据等说明。
完整规则保留在节点详情及打印摘要，不因时序图精简而删除；本次新增佣金控制后页面共101条。

系统与运营协作工作台为同一参与方；业务主体仍按节点承担资料提交、授权、物流、报关及确认职责。
各节点动作以彩色框定范围并在框内标明节点和动作；移除跨参与方的宽范围说明框，交互动作使用Mermaid激活/取消激活标记。

步骤1由A收集供应商/货物单证及C主体/送货地址后一次性填写，D自行填写付款主体及与C的商业关系。
运输信息由A收集填写，步骤1允许缺省；后续N06/N07按运输、申报要求补齐，不是后续豁免。
步骤1不对接收款银行：系统基于交易档案生成待审批资料并按规则检查资料的正确性，由人工审核员最终审批。
人工审核员审批通过后系统保存原件、记录关键字段、生成唯一交易单并关联交易档案；
原件及版本在文件存储系统，数据库保存关键字段、原件索引、交易档案与审核记录。
审批不通过不生成交易单；存储或关联失败保持待处理，不返回创建成功。
上述系统、存储及数据库操作为流程设计，当前离线页面没有真实后台或自动交易创建能力。
蓝色子流程为系统处理（建设需求），橙色为人工审核员经办审核，绿色为记录与交接；
核验未通过或前置条件不满足时退回补正，不进入下一节点。系统自动处理不能代替人工审批。
流程5展示D多笔汇款合一经CIPS打至B的银行账号，水单附言逐笔注明交易建档ID及金额，实际入账全额先记不可用；系统据此关联交易档案，人工审核员复核匹配结果。
同币种总分对账：入账本金＝已关联明细＋未匹配差额。仅按已关联且未占用额度生成国际付款发票INVOICE；
人工审核员批准当前材料版本后才交D并向收款银行申请贸易核验入账；CIPS是人民币跨境支付清算链路，不替代银行贸易真实性及合规核验。
银行核验通过且实际入账、银行可用状态确认后，仅释放对应CNH不可用额度为国内人民币可用余额；受理、内部批准或材料通过均不能单独释放。
CNH与境内CNY均指人民币，本环节不默认外币兑换。产品“不可用”是内部资金使用门禁，不代表银行冻结、法定托管或法律上的资金隔离。
未匹配、超合同额度及待核验差额独立受限挂账，保存原汇款、付款路径、责任人和账龄；不能自动转可付、收益或长期留作无贸易背景资金池。
本场景不提供退款操作；需要退汇时另由银行及合规确认正式处置程序，不预设36个月的合规宽限或自动退款。
原回单、分配ID、交易档案ID、INVOICE版本、内部审批、银行核验与入账可用凭证逐笔留痕，释放和银行回执均须幂等处理。

预览支持滚动、缩放、适配宽度，也可点击“收起源码”扩大图的显示区域；右侧可编辑Mermaid sequenceDiagram源码、更新预览、保存到本机、

4. 页面与四流实体
业务操作分两层导航：先显示工作入口目录，始终列出“01 建立交易档案”“关务系统”“02–07 内部运营工作台”；进入后仅显示该工作区当前岗位可见页面，并可返回目录。目录可见不授予权限，无权工作区显示明确提示；切换岗位保留当前工作区并重新核验。手机下拉仅含当前工作区页面，不再混入其他工作入口。
业务操作的“01 建立交易档案”向B运营经办、A业务经办及Super Admin开放，电脑侧栏与移动端授权工作入口保持一致；B运营可汇总建档资料，但不新增建档自审或终审权限，其他岗位仍按授权范围显示。
导航包括流程总览、四流实体、材料索引、业务操作、资金流设计；后两者为平级独立入口，角色手册和修订对照板块已移除。
“资金流设计 · V1”保留版本栏、账户资金图和一张“信息流”表格；删除账户价值、文件索引、撤销/冻结及后续全部说明卡片、示例和图示按钮。信息流标题下不显示追溯主链说明，表格后不显示运营原型说明。
V1的B收益为两项，均向D收取，路径统一为：D来款 → CNH不可用余额 → 银行核验入账并确认国内RMB可用余额 → 从该RMB可用余额扣费 → B独立收益账户。不得从CNH不可用余额直接转收益，不向A另行收费。
入账费：实收全额登记CNH不可用余额后按本金×0.03%（万分之三）计提一次；对应资金进入国内RMB可用余额后才实际过扣。重复回执、重新匹配不重复计费。
INVOICE申报手续费：每贸易交易单完成申报后计提人民币300元一次；对应D资金进入国内RMB可用余额后才扣取。草稿/内部批准不触发，补件、改版、重复申报不重复计费。
两项费用分别保存计提、待可用、扣划与收益到账状态，关联receipt_id/trade_id、银行核验及国内RMB可用凭证和双边回单；未确认可用、余额不足、冻结或路径未确认均暂停实际扣划。费用须有D授权及银行确认的适用核验/扣划依据，不能虚增货物贸易金额。
实收本金＝已实际扣划费用＋待扣费用预留＋剩余货款（含未匹配/已付A）。预留费用进入RMB可用余额后不得用于A付款，不重复占用或扣减；货款不足须D补足，不默认减少A合同应收。
V1不垫资：D货款实际可用且足额后才向A付款。V2支持B垫资：获批授信/自有资金 → 先行垫付A → D后续回款核验入账 → 按协议核销垫资并清偿；须独立授信、锁额及付款批准，不把CNH不可用余额作为垫资来源。版本栏为方案说明，尚未接入垫资执行。
本次修改仅为独立“资金流设计 · V1”展示与信息表；其他业务工作台及可编辑四流/步骤图仍保留各自规则，不代表已同步为新收费执行系统。离线原型不执行真实扣费、核验、入账或付款。
四流实体包括货物流、报关流、资金流、退税流四份详细实体流转图，每个状态标注责任方及原节点。
各图展示业务对象、状态变化、角色交接、条件判断及异常回路，不是数据库ER图，也不表示实时业务进度。
资金流明确区分出口后付款与出口前预付；B垫资无需先有D付款，但必须核对有效授信、占用及审批。
退税流展示交易档案材料收集、系统生成并检查待审批资料、人工审核员审批、授权经办人通过官方税务系统申报、系统按日或税务通知跟进、补正资料再次审批及实际到账核验；申请受理不等于退税到账。
实体图源码独立按图保存，不与时序图或Review记录混用；支持本机编辑、保存及下载.mmd。
审核演示及节点卡点操作入口均已移除；保留正式材料Review与人工校验规则说明。
账号分权、任务分派、自动校验、通知、外部接口等为系统建设需求，非当前已实现能力。
本页无真实人员认证、防篡改审计、支付、申报或后台接口，不可作生产审批。
