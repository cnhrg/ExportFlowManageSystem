# 电子合同法律调研与对外签署方案

> 核验基准：2026-10-25。范围：中国大陆法为主，覆盖代理出口全部对外主体及跨境风险识别。本文是法律研究与产品设计依据，不是针对具体交易的正式法律意见，也不保证司法、仲裁、银行或监管机关采纳。法规、合同及具体国别适用应在签约和上线前复核。
>
> 交付属性：调研与设计，**不是已上线能力**。没有改造原型、接入电子签平台、执行真实签署或建设生产数据库。

## 1. 结论

**建议采用第三方电子签平台，但建设重点不是“生成PDF并盖红章”，而是证明真实当事人、有权签署人、真实意思、确定内容、签署时有效性与完整履约证据。** 当前代码只能演示合同草稿及本机操作，不能出具真实可靠电子签署证明。

对外签署应分三层：

| 层次 | 本业务重点 | 建议处理 |
|---|---|---|
| 形成或实质改变权利义务 | 平台服务、出口代理、实际销售、物流、报关服务、第三方付款关系、扣费、重大账户指示、和解与补充协议 | 优先可靠电子签；先明确主体、授权、条款和生效约定。特殊/境外情形可走经法务确认的纸质或其他方式 |
| 履约确认或交付留证 | 报关最终草稿确认、报价接受、运输指示、提货/POD、收款确认、资料交接 | 按风险及有效主合同分层。高风险确认建议可靠电子签，常规事项可用身份与版本受控的明确确认，不一律重复签主合同 |
| 内部审批与正式机构结果 | 付款放行、结案审批、银行核验、海关放行、税务签发与申报结果 | 内部审批不代替外部同意；正式结果按主管渠道取得，不要求机关参加商业电子签流程 |

这里“建议可靠电子签”主要是风险控制选择，**不表示法律强制所有环节使用第三方电子签、CA证书、刷脸或公司章加个人签名双签**。

本项目需优先解决六个问题：

1. **平台服务法人和 B 贸易代理法人不同。** 各自合同、印章、授权、数据处理及责任边界必须分开；平台不能用自己的章代 B 或其他企业作商业承诺。
2. **C 是收货角色、D 是付款角色，不等于真实买方。** 销售合同、代收授权、付款指示和费用承担必须符合真实关系，不可根据字段自动构造。
3. **N04 缺真实报关合同正文，正式委托主体仍需确认。** B 列为境内发货人时，不得直接认定只有 A—F 合同即可完成正式报关授权。
4. **物流模板甲方为 B，流程要求 A 委任 E。** 先明确真实合同/转委托链，不能直接替换名称。
5. **现有合同存在付款、生效、免责及争议条款缺口。** 电子签不能修复错误合同内容，也不能自动解除银行限制。
6. **归档必须能独立调取、验证、出证。** 本机日志、截图、供应商网页或区块链标签不能替代完整证据。

逐文书规则见[签署矩阵](电子合同签署矩阵.csv)，审计及异常场景见[验收用例](电子合同审计验收用例.csv)。

## 2. 范围、身份与责任

### 2.1 已确认边界

覆盖 A 供应商、B 贸易代理、E 物流、F 报关、C 境外收货人、D 付款方及确实存在的承运、仓储、境外服务方。研究实际买卖方，不根据上述字母预设法律地位。

供应商未选定；代码中的法大大仅为演示。支持两种签署入口：外部人登录本系统后跳转；发起人分享签署链接。两者核验强度一致，不强制所有受邀人注册完整平台账号。境外不支持或不接受电子签可采用经法务确认的纸质/其他合法方式，但状态及证据不得伪装成可靠电子签名。

不包括实际供应商报价/认证、境外各国全面法律意见、最终合同审定、生产代码/DDL、真实支付/申报，以及新设垫资、退款或担保业务。

### 2.2 双法人责任图

```text
平台服务法人 ──平台服务/技术委托/数据处理安排── B贸易代理法人
      │                                           │
      │受控邀请、传输、存储及技术调用              ├──代理合同── A
      │                                           ├──按真实关系── E/F/境外合作方
      └──按实际采购/用户关系── 电子签平台 ──实际服务链── CA/印章服务

真实卖方 ──销售合同── 真实买方
真实买方/债务人 ──真实付款关系── D
有权债权人/收款人 ──付款及代收安排── B（如适用）
```

箭头不代表当然的连带责任、代理权或同意数据转委托。平台不因提供入口就成为贸易合同一方、收款方、付款担保人或印章所有者。实际采购方、CA证书申请人及对外签约人可能不同，须以实际合同和业务规则确认。

登录用户、组织成员、交易参与方、企业签署代表、用章授权人、技术调用者分别建模。平台管理员即使能维护租户，也不得当然使用租户企业印章。平台代发任务的技术授权不等于代替签约方确认意思表示。

## 4. 法律框架：法律效力不是一个布尔值

以下引文仅摘必要短语；完整原文链接见第13节。结论区分：**法**为法律/现行规范要求，**约**为具体合同约定，**控**为内部控制，**荐**为举证或技术增强建议，**待核**为具体适用或供应商能力未确认。

| 依据 | 条款/短摘 | 法律结论与产品含义 |
|---|---|---|
| L01《电子签名法》2019年修正 | 第3条：“当事人可以约定使用或者不使用电子签名、数据电文” | **法**：普通商事文书通常可电子化；仍须检查法定例外、特定监管文件及约定形式。拒用电子签不当然使交易无效 |
| L01 | 第4—8条：可调取查用、原件完整、可靠保存及真实性审查 | **法**：保留原始内容和来源、收发时间、完整性与调取能力。不是把签名图片贴上PDF就满足 |
| L01 | 第13—14条：“可靠的电子签名与手写签名或者盖章具有同等的法律效力” | **法**：识别签署人专有、签署时控制、签名改变可发现、文书改变可发现；也需关注当事人约定的可靠条件。图像章、验证码或PDF格式本身不证明四条件 |
| L01 | 第16、18、20—24条：第三方认证、许可、查验、证书与保存 | **法**：需要第三方认证时依法提供；不要求每份电子合同必须购买CA服务。**荐**：本项目核心合同选合规第三方方案；电子签SaaS品牌与持牌CA可为不同主体，需查真实责任链 |
| L01 | 第26条：境外证书经核准后的同等效力 | **法/待核**：核准条件不能省略；也不能倒推出其他境外电子方式一概无合同效力，或境内签署在境外自动可执行 |
| L02《民法典》 | 第137、140、143条：意思到达、沉默、真实意思与合法性 | **法**：短信送达、已阅读或沉默不是万能的签约合意；系统消息状态不等于法律成立或有效结论 |
| L02 | 第162、165、169—172条：代理权限、书面授权、转委托、职务行为、无权及表见代理 | **法**：实名不等于代表权；保存事项/权限/期限等证据。权限有争议由法务判断，不由系统一键宣判合同无效 |
| L02 | 第469、483、490—493、502条：书面、成立及生效 | **法/约**：数据电文可以是书面形式；依订立方式、履行与约定确定成立/生效。签署任务未完成不必然意味着合同未成立；签完也不一定满足附加生效条件 |
| L02 | 第496—498、506—507条：提示说明、格式条款、免责及争议条款 | **法**：重大条款合理提示并按要求说明；形式上的“已勾选”不修复实质违法或不合理条款。合同其他部分无效也不当然消灭争议条款 |
| L03《电子印章管理办法》国办发〔2025〕33号 | 第2—5、12—23、28—29、35、38条 | **现行规范**：自印发之日起施行，涵盖制作、备案、使用、注销及验证；“谁所有、谁控制，谁签章、谁负责”。第35条内部章安排不能直接作为对外章方案 |
| L04民事证据规定 | 第14—17、90、93—94条：电子数据、原件、外文、真实性 | **法**：邮件/微信/日志可作为电子数据；截图不天然充分。需审查生成、储存、传输、提取及关联证据；境外文件证明和中文译本按文件性质及适用要求处理 |
| L05在线诉讼规则 | 第15—19条：上链后与上链前真实性分别审查 | **法**：上链不是交易真实、授权充分或内容合法的保证。区块链、公证和第三方见证可按争议风险选择，非每份合同必需 |
| L06个人信息保护法 | 第13、17、19、21、23、28—30、38—39、47、51、55—56条 | **法**：合法性基础、最小必要、委托/提供关系、敏感信息及出境、保留删除与影响评估分别判断，不能用一份隐私勾选替代全部依据 |
| L07跨境流动规定 | 第3—10条：分类、豁免、机制和其他义务 | **现行规范**：不含个人/重要数据的贸易数据与含个人数据分别判断；免某些机制不等于免告知等义务。企业间合同不直接适用“个人作为一方”的必要履约豁免 |
| L08人脸识别办法 | 第4—10条，2025-06-01施行 | **现行规范**：评估必要性及影响；有其他同等方式时不得仅允许刷脸，应提供合理便捷替代，不为“证据更强”无条件多收生物识别信息 |
| L09会计档案办法 | 第8—9、12—19条 | **现行规范**：被纳入会计档案的材料按分类满足电子归档、最低期限及未了事项要求。不能推定所有合同/日志一律30年 |
| L10仲裁法2025年修订 | 第27—30、41、96条，2026-03-01施行 | **法**：普通仲裁协议的事项/机构须明确，欠缺有补充及效力风险；结合涉外特别规则审查，不套旧法条号或认为全部跨境约定都自动执行 |
| L11单一窗口委托指引 | 委托方对应进出口收发货人；具体要求询主管海关 | **待核**：是正式渠道核实线索，不据此替主管机关确定本笔双抬头授权；民事A—F安排、A草稿确认、B认可及正式委托分开 |
| L12 GB/T 38540—2020 | 官方标准信息与适用性 | **技术参考**：推荐性国家标准不等于合同有效的独立法定要件；按实际标准及供应商实现/检测材料复核 |

### 4.1 不能合并的八项判断

分别记录电子形式适用性、当事人/代表权、明确意思、合同成立事实、约定/法定生效条件、签名可靠及验证、证据完整可用、境外争议与执行风险。系统只记录核实事实及责任人，不能裁判最终法律效力。

当前模板存在“签字盖章后生效”的约定，需按经审定合同履行或先修订，不能用“法律一般允许电子签”自动删掉代表签字或企业章要求。法律不普遍要求双签，但**本笔约定可能要求**。

### 4.2 近期规范状态的处理

R01为工信部2026-10-23公布的《电子认证业务规则规范》等14项行业标准报批公示，公示期2026-10-24至2026-11-22。**公示稿不当作已生效行业标准**。本轮未取得网上流传的统一整改期限、所谓四项职责和证书等级限制所对应的主管部门原始通知，故不采作本项目的普遍强制要求。

供应商须提供其实际适用文件、正式标准及CPS版本、变更影响和服务连续安排；团体标准、合同承诺、监管通知与法律分别标注。官方来源目录是本研究已核验范围，不代表穷尽全部行业、地方和国别规定。

### 7.1 两条入口的完整行为

**登录入口**：登录 → 服务端确认组织/本人/合同访问及签署席位 → 检查批准版本和有效授权 → 取得短时第三方地址 → 第三方/CA按规则核验并取得签署意愿 → 签署 → 服务端验通知并查单 → 验证内容和签名 → 下载归档与交付 → 独立核实生效条件及业务门禁。

**分享入口**：有权发起人申请邀请 → 服务端绑定合同、版本、受邀主体及席位、有效期与用途 → 受邀人打开最小邀请页 → 核验其确为受邀主体/代表及有权签本笔 → 进入同一第三方流程。无需完整业务账号不等于匿名签署；持链者不能直接下载正文或取得企业用章权。

两入口使用相同核验标准并共享签署事实；反复打开、切换入口或补发链接不得重复创建合同任务。分享不等于授权转委托，换签人必须审查新的权限并保留历史。

邀请投递、阅读、签署、文件交付分开记。链接撤销不删除历史，也不解除已生效合同。不在URL放身份证、完整手机号、银行账户或可长期复用的供应商令牌；日志不得落可直接签署的明文地址/令牌。外部通知不泄露敏感正文。

### 7.2 内容一致性：不要比较错误的哈希

签前固定正文与附件、审批版本及业务关键字段。供应商如进行模板填充、格式转换或增量签名，保存处理清单及其与批准内容的可验证对应关系。

**签前文件和签后PDF的整文件哈希通常不相等**，不能据此判定篡改。分别保存批准文件摘要、供应商待签文档标识及内容映射、签后文件摘要、签名覆盖范围、附件范围和验证结果。多签时核验各签名覆盖的版本及后续增量变更；最后完整文书须与全部必要当事人的实际确认范围相符。

下载原件后不加水印、不重排、不“另存PDF”覆盖原始签署件。展示/脱敏/打印副本独立留存、标注用途并指向原件。验签报告只能说明其覆盖的对象和规则，不等于合同内容合法。

### 7.3 状态与事实分离

| 维度 | 建议状态/事实 | 不可作的推断 |
|---|---|---|
| 内容与审批 | 草稿、送审、批准/退回、因版本变更失效 | 批准不表示对方签署 |
| 任务与各签署席位 | 已邀请、核验、待签、部分完成、拒签、到期、撤回、处理中、未知、完成 | 页面返回或渠道提交不表示完成；不硬编码只有两方 |
| 签署验证 | 待取件、待验证、验证通过、验证失败/需人工核实 | 供应商success不直接改为有效 |
| 归档与交付 | 待下载、下载失败、已校验归档、证据不完整、各方交付/接收 | 下载失败不抹去已发生签署；接收不表示放弃权利 |
| 成立/生效核实 | 已核实事实、条件待满足、条件已核实、待法务判断；依据及责任人 | 不是自动法律裁判。系统缺证不直接宣称法律上未成立 |
| 业务资格 | 可办理、暂停、重审、外部已发生结果 | 已签不自动付款/报关；解除内部审批不反转银行或监管事实 |

任务未知时查询原任务，不用新键盲重发。部分签署后改内容先核外部实际状态，保留已签方及旧任务，通过新版本/新文书重走适用审核和签署。生效合同变更/解除用关联新文书及相应通知，不回退原合同为未签草稿。

## 8. 证据包、审计与保留

### 8.1 每份重要文书的证据清单

| 包内分组 | 最低应证明的内容 |
|---|---|
| 业务/当事人 | 文书ID及交易/批次关系、真实当事人及其时点快照；平台与B区别；真实买卖及第三方付款关系 |
| 身份与授权 | 签署自然人身份核验引用、代表资格、代理/用章事项及期限范围、当时授权状态；不重复收集无必要的身份影像 |
| 意思及条款 | 电子方式合意、批准正文及附件、重大条款提示/说明与接受、每个必要当事人实际签署范围 |
| 签署与验证 | 签后电子原件、摘要、签名/印章、签署时证书及印章状态依据、证书链、可信时间证据及验证报告/策略版本 |
| 渠道与交付 | 发起/通知/查单关键原始证据、回调验真及来源、各方取件/交付和必要接收依据；投递与法律送达不混同 |
| 履约及变更 | 草稿确认、运输/POD、正式回执、银行与收款/结算、变更/解除/和解及其版本关系 |
| 归档和出证 | 文件精确清单、来源、提取人/方法/时间、权限批准、验证说明、完整性清单、导出日志及必要译文 |

证据包独立归我方受控保存，不能只留供应商链接、报告截图或平台“司法认证”标识。供应商原始认证材料的合法保管、争议调取权、格式、响应及收费写入服务安排；避免为了“拿全证据”把人脸、证件等全部复制到我方。

### 8.2 长期验证与可信边界

签名验证须说明签署时证书/印章是否有效、身份/授权证据是否支持、签名覆盖何内容、时间证据及后续改动。事后自然到期不当然否定签署时效力；事后吊销或密钥泄露须依据发生时点及证据评估，也不能只看当前状态放行。

采用独立只读/不可改存储、封存清单、备份、权限隔离、周期验真及恢复演练等手段抵抗覆盖、删除与管理员重建。哈希链帮助发现一致性变化，但不能独立证明原始真实、未删漏或可信发生时间。区块链、公证、司法鉴定等按证据争议选择，不承诺“上链必胜诉”。

审计只读权限不自动有证据导出权。查询、批量导出、跨组织共享、下载、委托律师/仲裁提交分别核查范围与用途；每次下载重新鉴权并记录。下载链接失效和保管原件是不同动作。

### 8.3 分类保留表：没有统一“合同保存几年”

| 类别 | 已核实规则/策略 | 起算点及责任 |
|---|---|---|
| 合同、附件、履约及变更证据 | 结合文书档案、税务/海关/行业、债权未了事项及争议需求确定；本报告不设通用年限 | 法务/档案/业务确认适用分类、起算点、最短期限及必要延长 |
| 被归为会计档案的凭证等 | L09第14—15条依分类通常有10/30年等最低期；第19条未结债权债务等不得按一般到期销毁 | 按会计年度终了后第一天起算的规则及具体分类执行，财务档案负责人确认；非所有合同一律30年 |
| CA认证相关信息 | L01第24条由认证服务提供者至少保管至证书失效后五年 | CA法定义务；我方仍需独立确定合同/证据保留，不拿此期限替代 |
| 个人信息影响评估报告/处理记录 | L06第56条至少三年；L08人脸评估另有对应要求 | 隐私负责人确定具体起算和变更记录；不表示人脸原始影像应一律保存三年 |
| 身份影像、人脸及其他敏感信息 | 必要最短保存、严格保护；合法性基础及适用同意分别判断 | 能用核验结果/受控引用证明则不重复存；供应商持有也需核查责任和争议调取 |
| 日志、草稿与失败尝试 | 按适用法律、事件调查、合同和审计需要分类；不写死所有记录永久存 | 安全/审计/法务指定政策、生效版本及到期审查，不因统一日志而合并期限 |
| 法律保全范围 | 调查、未了争议等适用保全期间不得按一般定期清理 | 有权人员确定范围、原因、依据及解除；独立批准并保存操作证据 |

三年诉讼时效不是统一档案删除期限。既有设计“全部revision留档”应落实为：**在合法保留和保全范围内，不因换版、逻辑删除、访问撤销或链接到期清除历史**；不能扩张为所有个人信息无限保存。期限/删除请求冲突交法务确认，符合L06第47条情形时按要求删除或限制处理并记录依据。需要变更既有保留策略时另行批准，本文不执行删除。

## 9. 个人信息与跨境场景

### 9.1 数据处理角色

按实际决定目的/方式的主体，区分平台、B、电子签平台、CA和印章服务的受托处理、独立处理或共同处理。不是在协议中称“受托方”就自动成立，也不把所有接收方一律当受托人。

委托处理明确目的、期限、方式、信息种类、保护措施、权利义务及监督和转委托；独立提供、敏感信息、出境分别核对法律依据及适用的告知/单独同意和影响评估。企业合同签署人通常不是该企业商业合同的自然人当事人，不能仅靠“履行公司合同”笼统免除个人信息义务。

区分平台使用条款、隐私告知/同意、电子方式合意、企业代理授权、用章授权、关键条款确认。拒绝不必要的人脸核验不应自动剥夺其他合理便捷核验路径。

### 9.2 跨境四个独立问题
