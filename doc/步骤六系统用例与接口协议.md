# 步骤六：代理出口货物证明系统用例与接口协议

## 1. 范围及未决规则

本步骤包括准备材料、申请办理、核实证明，以及出口代理交付、供应商接收核对，对应N18至N20。出口代理申请、报关代理协助的职责分工仍须主管税务机关确认。职责、范围、时限、渠道或验真规则缺少正式依据时，可先备料，不能正式申请。不能默认一笔交易或一张报关单对应一份证明，也不能自行合并申请、假定36个月期限或自制附件3。内部批准、系统保存请求、机关提交和受理、签发、发送、收到及核对通过须分别有记录。

本交付为静态协议、离线用例模型和有限隔离验证驱动，不是生产REST/RPC handler、真实IAM、正式税务渠道或自动调度。原创合成材料不得充当官方回执。复验结果由调用者显式指定保存路径；无外部接入的正式申请、受理、签发和交接成功必须明确未验证。

## 2. 目标与演员

12个用例说明经办人如何查看职责和缺项、建立申请协作档案、整理并提交材料、独立审核或退回补充、申请正式办理和查原结果、核实税务回执、补材料重审、核实证明及更正撤销、交付证明、接收核对或提异议、处理异议并重新交付，以及查询历史。

用例图分别列出供应商、出口代理、出口报关代理、独立税务审核员和主管税务机关。经办人不能自审；外部用户须有本交易的主体授权，内部审核员使用自己的内部身份。每个用例有业务黑盒图和事务、中间件实现图，默认原图70%，源码位于[step6](examples/step6/)。

## 3. 唯一共享主模型

唯一DDL来自`doc/sql/domain/schema.sql`，本步骤不生成第二套核心DDL。实体/闭合载荷逐字段映射见[entity-projection.json](examples/step6/entity-projection.json)。

- `tax_case_tab`：type=1证明/type=2退税，本步骤只读写type=1；UK `(trade_number,tax_type_code,scope_reference)`；证明`claimed_amount IS NULL`，不是0，币种CNY。`version`控制强ETag。正式scope只能由确认规则计算并核重叠，客户端不能随机指定。准备期主模型允许服务端确定的待确认占位，本步骤创建正式协同案入口缺确认规则时409，不拿占位冒充已确定范围；预检及已有准备案可备料。
- 案件状态：1准备、2待审、3待提交、4正式已提交、5正式受理、6补正、7处理中、8正式处理完成但未全部交接核对、9全部交接核对、10终局拒绝、11撤销。8不等于9，10/11不自动正常结案。
- `tax_submission_tab`：内容、manifest、摘要、前版、补正引用不可修改；新材料另版。`submission_content_json`严格沿共享§11：`schema_version=1,tax_type_code=1,approved_snapshot_number,scope_reference,rule_version,responsibility_basis,declaration_references,fields,check_report`。`SubmissionInput`按白名单映射这些字段，不额外包自由JSON；源版本向量在`check_report`，经办身份在`submitted_by`。严禁只存文件集合。`review_snapshot_json`初次未审NULL，之后严格为`reviewer_reference,result_code,reviewed_at,content_hash,rule_version,evidence_references,comments?`，后续决定另追加事件。`previous_submission_revision_number`/`correction_event_number`内部首版NULL；正式补正引用原版和已核实正式补正事件。内部退回不捏造官方补正号。
- 提交状态码1待审、2退回、3批准、4提交待核、5正式提交、6受理、7需补正、8被替代、9结束、10批准失效；执行码1未发送、2执行中、3未知、4明确未提交、5已有提交回执。正式提交回执不是受理，执行未知不是失败，不释放未决执行。
- `tax_event_tab`：类型1建案、2材料版、3审核退回、4内部批准、5办理意图、6正式提交、7受理、8补正、9处理中、10签发/更正、11终拒、12撤销、13证明交付、14证明接收/核对/异议、15证据声明、16核实/异议处置决定、17资金到账核对（步骤七消费）、18批准失效。结果1已记录/2有权核实通过/3退回，不擅加事件码。类型6..12必须确切提交版、真实external_event_key和authority_reference_number；内部事件外部键NULL，可信actor_reference由服务端注入。
- `event_payload_json`严格沿共享§11，公共`schema_version=1,operation_evidence_reference`；准备分支为scope/unresolved_items；材料/审批分支为`submission_content_hash,reviewer_reference?,reason?`；正式分支为`dispatch_reference,source_namespace,authority_reference,evidence_references,outcome_code?`；交接分支为`delivery_number,proof_file,recipient_reference,received_delivery_number?`。交付13、接收14、核实/处置16按Proto具体字段映射；交付/接收绝不藏通用middleware。官方更正仍用类型10、撤销12；老版保留但不得新交付，更正后重新取得A核对。

交接和异议须记录签发依据、收到/核对通过/异议，以及原异议和实际处理凭据。共享§11已定义`certificate_event_number/receipt_outcome_code/objection_event_number/disposition_evidence_references`等封闭分支字段，必须按该规范保存，不能自由添加JSON键。当前实测仅证明缺正式证明时不能交付或接收，没有验证正式交接成功。

文件用途18报关草稿、19供应商确认、20正式报关文件、21官方回执、22代理出口货物证明、23交付接收、24退税材料、25银行费用依据由主模型维护。协议`FileVersion`含固定VersionId；SQL业务清单使用共享`FileRef={logical_file_number,revision_number,content_digest,document_purpose_code}`，精确VersionId由不可变文件元数据storage_path解析并与清洁扫描任务一致核对，不另造非白名单字段。上传成功不等于清洁可引用；缺文件、感染、扫描过期/失败都阻断。

## 4. 事务、独立审核与外部事实

共用步骤一身份/请求确认/文件上传/取号/原受理技术能力。不新增通用“税务业务封套表”存权威业务事实。先当前身份与对象授权，再原subject/audience/key查重；同键异文409。READ COMMITTED短事务固定交易根→案件→按版本排序提交→按id排序事件，锁后当前读并重查原键与版本。ETag绑定案件version、源交易批准版及依赖事件尾，不允许旧版材料沿用旧批准。

经办与独立审核身份必须不同；读取审核上下文后批准确切`package_hash`与源版本向量。修改材料或源附件2/交易批准版变更，受影响未执行批准失效并重审。正式补正新增版，原正式提交与官方事件不可覆盖。内部退回只新材料版，不造官方事件。所有业务事件/当前投影/最小原受理结果/技术outbox同一COMMIT，故障全回滚。

S3/ClamAV/主管渠道I/O在事务外。正式办理必须职责、范围、时限、正式渠道、当前独立批准、确切文件均满足；外部未接入返回`OFFICIAL_CHANNEL_UNAVAILABLE`，不派发模拟成功。办理意图只记录原`dispatch_reference`。未知保持原号，查原办理/主库受理；不得新号重派。证据上传只是声明；独立核实真实源、确切提交版、原办理号、官方稳定键和附件2范围后才追加6..12。验签/传输失败不能当机关终拒。

正式证明核实完状态8仍需B交付事件13和A独立核对事件14。B代A点确认、收到即默认核对、更正沿用旧接收均拒绝。异议未实质消除不状态9；需官方更正则等待真实更正证据并重交付/重核对，不用“已解释”清零。终局拒绝/撤销保持历史，不自动发起退税或结案。

## 5. 强资源REST与显式RPC

17个接口、2个受众服务，所有方法独立`FooReqMsg/FooRspMsg`，HTTP每条明确`response_body:"resource"`。资源使用`tax-proof-cases`、`submissions`、`reviews`、`dispatch-intents`、`official-evidence-claims`、`official-verifications`、`deliveries`、`receipts`、`objection-dispositions`、`history`和原请求`tax-proof-command-results`，不使用万能action路径。提交版路径参数uint32，其他业务号受限ASCII，路径/query严格白名单，拒未知/重复query及编码斜杠。

完整逐接口输入/RESPONSE/cURL/RPC见[HTTP全集](examples/step6/http-reference.md)、[HTTP JSON](examples/step6/http-examples.json)、[RPC JSON](examples/step6/rpc-examples.json)、[接口清单](examples/step6/http-contract.json)和[Proto](../proto/trade/taxproof/v1/taxproof.proto)。HTTP仅JSON、十进制定点字符串；不适用金额不出字段。cURL没有真实凭据/签名，不可直接冒充业务执行。

读取客户端/服务端预算5000/4000ms；写10000/8000ms。RPC必须deadline，缺失`DEADLINE_REQUIRED`；metadata映射authorization、idempotency-key、if-match、confirmation-id，内部受众由凭据验证，不能靠客户端自报。写要求原意图确认、强If-Match和UUID幂等键，确认绑定subject/audience/方法/路径/规范化内容/当前版本/原键。读取重试最多3次且总预算内；写超时只原键原文原标签恢复，不自动换键。

成功创建201并返回Location/强ETag，读取200/no-store；原受理回放保持原状态码、Location、ETag和原资源，不返回最新状态冒充原结果。错误统一`application/problem+json`、强类型`trade.filing.v1.HttpProblem`：`type,title,status,detail,instance,errors[{pointer,code,detail}],outcomeUnknown,retryAfterMs`，无成功resource。RPC错误例为`error:{code,details}`，code为规范gRPC状态，details严格`trade.filing.v1.RpcFailure`：`code,httpStatus,errors,retryable,retryAfterMs,outcomeUnknown,requestReference`；例带`errorType/httpErrorType`，无response/resource，不伪装RspMsg。8个故意失败例保留7个409/FAILED_PRECONDITION和1个404/NOT_FOUND；`contract.status`仍表示正常成功状态字符串201/200，不能要求负例状态等于它，错误也不要求Location/ETag。无权与不存在统一404；当前权限被撤销不因原键绕过授权。

|业务错误|HTTP/RPC|恢复|
|---|---|---|
|INVALID_INPUT/UNKNOWN_FIELD/INVALID_IF_MATCH/DEADLINE_REQUIRED|400 INVALID_ARGUMENT|修字段，不乱重试|
|UNAUTHENTICATED/CONFIRMATION_EXPIRED|401 UNAUTHENTICATED|重新认证及确认确切意图|
|FORBIDDEN/SELF_REVIEW|403 PERMISSION_DENIED（自审门禁可409 FAILED_PRECONDITION）|合法独立身份，不切受众绕过|
|NOT_FOUND|404 NOT_FOUND|不猜案号|
|IDEMPOTENCY_CONFLICT|409 ALREADY_EXISTS|停止同键异文|
|SCOPE_RULE_UNCONFIRMED/RESPONSIBILITY_UNCONFIRMED/DEADLINE_RULE_UNCONFIRMED/OFFICIAL_CHANNEL_UNAVAILABLE|409 FAILED_PRECONDITION|补正式适用规则及真实通道|
|REVIEW_REQUIRED/SOURCE_REVISION_STALE/CORRECTION_CHAIN_INVALID|409 FAILED_PRECONDITION|读当前版并重审|
|OFFICIAL_EVIDENCE_REQUIRED/EXACT_SUBMISSION_REQUIRED/CERTIFICATE_NOT_VERIFIED/DELIVERY_STALE/OBJECTION_UNRESOLVED|409 FAILED_PRECONDITION|核实确切真实证据，不造外部成功|
|DISPATCH_UNKNOWN|409 FAILED_PRECONDITION|仅查原办理号|
|PRECONDITION_FAILED / PRECONDITION_REQUIRED|412 / 428 FAILED_PRECONDITION|读新标签、新意图重新确认；先查原键|
|DEADLINE_EXCEEDED/UNAVAILABLE|504 / 503 对应RPC|主库查原受理/办理号；不宣称失败或重复申请|
