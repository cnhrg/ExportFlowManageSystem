# 身份确认、电子签证据、取号与可靠性设计

适用步骤一、二；覆盖旧版“所有供应商请求必须自带私钥签名”的假设。供应商没有签名设备，用户确认不要求自管浏览器密钥，合同由第三方电子签平台实名签署。当前仅设计/离线合成资料，不表示认证、电子签、S3或恢复任务已上线。

本机开发验证已另行部署MySQL、私有S3、扫描、监控/日志及XXL-JOB后台，入口、可验证范围与未接入边界见[方案验证中间件环境说明](方案验证中间件环境说明.md)。这不表示本文件的应用模块已实现，也不表示S3或电子签已在对外生产环境上线。

## 1. 一个应用，两类接口

单体应用、一套MySQL和私有对象存储。对内运营`/internal/v1`与对外接入`/api/v1`使用隔离的路由、受众、凭证和对象/岗位权限；对外包括使用方及银行等机构，银行不在本轮新增接口。身份、编号、资料、合同、文件与定时恢复是进程内模块，不拆微服务、模块RPC、Redis、消息队列或分布式取号器。HTTP/可选gRPC复用同一处理、幂等和事务。

每用例先业务参与者—系统黑盒顺序图，消息表达目标/可观察结果，随后单体实现展开。采用本轮确认的《软件方法》表达约定，不声称复刻书籍原图。默认原图70%（不是fit后乘70%），保留100%/适配/放缩，局部滚动及键盘操作；切回页面不重置用户缩放。

## 2. 不给供应商增加密钥负担

采用“实名身份/组织经办授权＋HTTPS＋强认证＋具体内容明确确认＋不可改证据＋第三方电子签”的分层方案：

| 层次 | 设计与限制 |
|---|---|
| 传输 | HTTPS/TLS、服务端证书验证、HSTS；Cookie会话Secure/HttpOnly/SameSite及CSRF/Origin校验；机构按协议mTLS。HTTPS防传输窃听/篡改，**不独立证明用户同意内容或法律抗抵赖** |
| 身份 | 核实法定主体及经办授权；实名身份服务与已有登录集成，不能以自填公司名称或掌握交易号取得权限。强认证优先平台支持的通行密钥/多因素；签约由电子签平台按适用标准核验 |
| 确认 | 展示完整当前版本、差异、动作及材料摘要，用户明确点击确认；对敏感操作重新认证。不能仅凭自动勾选、短信到达、IP或普通登录宣称可靠电子签名 |
| 证据 | 固定版本正文/材料、身份及授权验证引用、确认文案版本、服务端时间、会话/重新认证审计引用、意图摘要及受理结果保全；IP/设备线索仅辅助且最小化，不进普通业务事件 |
| 合同签署 | 跳转第三方实名签署页；供应商在平台确认确切文档，平台管理证书、私钥控制、签署授权、时间戳与证据包。平台名称/资质、境内外套件、数据跨境、证据可导出性需选型验收，不假定供应商一定具有某种认证 |
| 平台回执 | 本应用受控平台密钥签署确定受理的原结果，供双方验证；不要求供应商拥有私钥。平台签名证明平台陈述，**不能冒充用户签名** |

不把统一私钥写进JS、localStorage或下发所有用户。浏览器Web Crypto可做RSA/ECDSA签验与RSA-OAEP/ECDH等原语，但本轮不自行建设浏览器PKI；SM2/SM3也不是通用Web Crypto原生能力，不能用RSA冒称国密。保密主要交给TLS和受控服务端信封加密，不把非对称加密误当用户同意。

机构系统未来可按登记策略使用国外RSA-PSS（≥3072/SHA-256、盐32）或ECDSA P-256/SHA-256，国内SM2/SM3及相应合规实现。既有`InvocationProof/S1-PROOF-1`仅保留为**可选机构契约**：签署所有InvocationClaims规范JSON、逻辑HTTP方法/路径、原业务键/标签/摘要、受众/主体/证书/时刻/nonce；ECDSA P1363、SM2 DER及绑定用户标识。机构私钥不复用作加密密钥；密钥绑定、吊销、授权、可信时间另行验收。普通供应商不必提供`X-Invocation-Proof`。

## 3. 操作确认凭据与事务内重入

### 3.1 创建与绑定

用户在HTTPS前端查看完整内容，选择明确确认后，前端调用`POST /api/v1/operation-confirmations`，正文`OperationIntent`含逻辑HTTP method/resourcePath/idempotencyKey/ifMatch/bodySha256。服务端使用已核实的主体/组织/会话/受众与重新认证记录生成随机至少128位确认号，有效300秒；不从正文接受主体或“已实名认证”标志。创建确认自身需要认证、CSRF和原幂等键，但不递归要求另一个确认号。

bodySha256来自类型重建后的正文；规则见HTTP规范，RPC取HTTP映射的正文子消息。服务端在实际写入时独立重新计算并比对，不能信客户端摘要等于实际内容。服务端持久确认记录至少包含：确认号、主体/组织/会话授权链、精确意图/规范摘要、确认文案版本、重新认证引用、创建/到期时间、幂等键、原受理结果引用。唯一确认号及主体/创建键，复用已有身份审计持久设施，不新增核心交易表。

`X-Confirmation-Id`或RPC `confirmation-id`只是引用，**不是代替Authorization的持有即授权令牌**。不能移植到其他主体/受众/方法/地址/正文/键/标签。强认证/会话续期可沿同一已核实会话链，独立新登录会话须新确认；不降低经办授权。

### 3.2 短事务

业务事务前保全受控身份/确认审计与原资料；失败不执行业务，孤立证据标未受理，按策略保留/清理。业务写入：

1. 当前身份/对象权限有效；BEGIN按预留→交易根→本地授权门禁→文件→确认固定锁序，先查询原请求结果。
2. 已受理同文先回放原结果，不因原确认过期重做；仍校验当前身份/授权和原确认归属。换会话需新确认，同意图可恢复原结果。异文409，不借新确认覆盖旧键。
3. 新请求检查确认未过期、与类型重建意图一致，事务内锁确认并标记原结果绑定；业务/事件/消费确认一次COMMIT。失败整笔ROLLBACK，不提前消费后使合法重试失效。
4. 确认过期且未受理返回401 `CONFIRMATION_EXPIRED`；重新认证按相同业务意图申请新确认，不改变业务幂等摘要。绑定不一致409 `CONFIRMATION_MISMATCH`。确认丢失/未提供400 `INVALID_INPUT`。拒绝后不能返回成功形状。

事件3封套版本3条件必填`operation_evidence_reference`，只存受控审计引用；旧`signing_evidence_reference`仅机构签名模式可用，二者不得同时冒充不同主体证据。旧合成数据库未接入真实确认，不称生产证据。主体、会话及证据不增加主生命周期状态，普通资料提交仍编辑中。

### 3.3 平台受理回执

仅确定COMMIT后生成`ReceiptProof/S1-RECEIPT-1`，平台密钥受控且保留历史公钥。签规范`ReceiptClaims`全部字段，受众为原主体，绑定原事件/请求键、公开业务摘要、原受理投影摘要及受理时刻。业务摘要为规范`{method,path,ifMatch,body}`的套件摘要，不公开内部HMAC。事件时刻不是精确数据库COMMIT时钟或天然可信时间戳。

交易资料用事件3；编号/文件等中间件写入`eventNumber=""`，以原资源/请求绑定键定位。先查已存原回执，无才签名并条件保存；签名随机性不产生新业务。HTTP `X-Receipt-Proof`及RPC成功尾metadata `receipt-proof-bin`。确定业务受理而回执不可用503 `RECEIPT_NOT_READY`、outcomeUnknown=false；后台自动恢复。COMMIT未知503 `COMMIT_OUTCOME_UNKNOWN`、true；先主库原键核实，不签未知成功。

第三方电子签的合同签名/证据包与上述平台操作回执不同，不能用平台回执代替合同双方签名。选定平台后验证签署人授权、证书链/吊销与可信时间、覆盖整个签署件及附件、原审批正文一致性、签名/文件未篡改，并本地受控保留原件和证据供日后验证，不只留一条平台URL。

## 4. 预取单号中间件

| 同库基础设施 | 字段/约束 |
|---|---|
| middleware_number_counter_tab | namespace主键、last_issued_value BIGINT UNSIGNED；迁移预建trade计数行，不在运行时无声重置 |
| middleware_number_reservation_tab | reservation_id、主体、namespace、原键、request_hmac/key_version、trade_number、created_at；预留号/交易号唯一，主体+namespace+键唯一，归属不可变 |
| middleware_file_upload_tab | owner_context（材料/操作证据/回执）、上传号/归属/原键/摘要、确切源版、最终键/适用文件号版、确认意图、阶段/attempt_count/next_attempt_at/lease_until/fencing_token/last_error_code/稳定结果；唯一资源及目标键 |
| middleware_command_receipt_tab | 步骤二命令的受理号、单调受理序号、主体/组织/受众/原UUID键、方法/路径/原标签、原HMAC与密钥版/规范化版本、业务根/目标版、操作证据及原最小受理投影/Location/ETag/时刻；UK(主体,受众,键)，与业务/消费确认同COMMIT；不是新增核心业务表 |

这些是待实现中间件设施，不改变五张核心表。编号`TRD`＋全局递增序号20位十进制，不日切、不依赖NTP；高水位迁移保留，BIGINT上限明确拒绝/告警，号码不回收允许空洞。DEMO业务号不是实际格式。

BEGIN先按主体/原键当前读预留；已有同文返回原号、异文不增号。未查到不等于锁住不存在行：锁预先存在的固定计数行，获得锁后再次当前读原键，无才递增并插预留，计数/归属/确认消费同事务提交。缺计数行配置错误，禁止默认为0。

死锁/唯一冲突/确定回滚在剩余预算内最多新开2次事务，每次先查；失败事务不能继续写。COMMIT未知先主库原键恢复。资料创建先锁原预留再查原交易/原创建事件，无才INSERT；唯一键是兜底，不是“先INSERT触发冲突”重入实现。修改先锁交易根查原事件，同文回放早于当前If-Match。远程认证、扫描、复制及签名都不持业务根锁。

## 5. 文件与证据自发重试

浏览器原字节上传连接5秒、单次60秒、无进度15秒、最多3次含首次，等待1/3秒加0–20%抖动，总200秒。原对象键/摘要不变，过期签名URL重新鉴权获取；摘要冲突/恶意内容/持久403不重试。关页后未到服务器的字节不能后台补造，显示awaiting_upload。

确认接口BEGIN先查原任务/文件/结果，新请求才记录持久确认意图与原键。应用启动及每5秒扫描恢复任务，不依赖用户再点确认，也无消息队列。每次先查完成结果，再领取60秒租约/递增栅栏；20秒续租，失败不得旧栅栏提交进度，I/O期间不持数据库锁。

| 阶段 | 恢复与不变量 |
|---|---|
| HEAD/GET | 固定私有暂存键/真实版本/长度/摘要；尚未上传不当成功 |
| 扫描 | 实际字节、类型、长度及扫描版本/结果；未知不当通过，恶意/摘要冲突rejected |
| 最终复制 | 复制前持久绑定文件号及最终键；先HEAD，只有不存在才条件写；已有完全相同才复用，冲突禁止覆盖 |
| 元数据 | BEGIN先查原任务/文件号版，无才INSERT；元数据与完成结果同事务；未知COMMIT先查，不换文件号 |
| 阶段失败 | 保存稳定阶段/attempt_count/next_attempt_at，重启仍恢复，不把计数清零 |

对象连接3秒/HEAD总5秒，读取/复制/扫描单阶段30秒。一次尝试不叠SDK重试，最多8次/24小时；等待1/3/10/30/60/300/900秒加抖动，尊重Retry-After且受24小时限制。数据库确定死锁最多2次内部重试，计入当前尝试。超限manual_action＋最后错误＋告警，授权人工沿原任务恢复，不另造成功文件。

操作证据预写/平台回执同样稳定键与持久有界恢复。证据不伪装业务材料、不插入重复文件行。回执任务先核实原事件/中间件提交，绝不为未知结果签成功。孤立最终对象是待恢复而非可引用成功；清理检查全部历史引用/证据保留策略。存储适配器须支持不可覆盖、版本核验和保留策略，否则阻断上线。

步骤二第三方电子签任务也先本地持久绑定clientReference→合同确切版本/正文摘要，COMMIT后才远程发起。超时先按原clientReference查单，平台无幂等/查单能力则转人工，不盲目新建。签署意图24小时发起恢复期限不等于合同法律期限；最长重试8次，已发平台任务超出本地恢复期限仍可能真实生效，必须保留未知门禁直到平台确定撤销/完成。回调验签、去重、查单核实、结果归档及人工恢复详见步骤二规范。

## 6. 规范与来源

- HTTP/RPC逐接口deadline、错误/重试预算见[步骤一接口规范](步骤一HTTP接口协议.md)及[步骤二规范](步骤二系统用例与接口协议.md)，均为设计默认不是银行确认值。
- [电子签名法官方文本](https://wap.miit.gov.cn/zwgk/zcwj/flfg/art/2022/art_4ed0e4a46946479c90a9e0f2c76a11ef.html)：第8条证据真实性考虑因素、第13/14条可靠签名条件及效力；本项目不能因HTTPS或某厂商名称自动断言符合。
- [MDN Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/Web_Crypto_API)、[generateKey](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/generateKey)：提供密码原语，不包办身份/密钥控制或合同法律效力；本轮不实现浏览器PKI。
- [法大大公开产品说明](https://www.fadada.com/)仅确认有第三方电子签/API产品类别，具体API、签名算法、幂等/回调/超时与证据格式**待选型联调**，未复制或杜撰厂商接口。
- [gRPC deadlines](https://grpc.io/docs/guides/deadlines/)、[status](https://grpc.io/docs/guides/status-codes/)：deadline不证明写入未提交，原键恢复仍必要。
