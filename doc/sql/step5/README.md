# 步骤五资金实体与事务约束

本目录是步骤五用例对共享资金领域表的读写说明，不生成另一套资金表，也不替代
`交付成果/assets/domain-model.js` 与 `doc/sql/domain/schema.sql`。服务费事件码12
`agency_service_fee_settled`表示首次获批分账时，从D已核验可用余额一次性结算固定CNY 300；
不是银行扣款，不新增货款桶。事件8/9/10保留为历史兼容事件，新业务不生成。
事件11 `bank_fee_debit`仍表示有真实凭据的银行费用扣款。

## 实体映射

| 业务事实 | 权威表 | 规则 |
| --- | --- | --- |
| 账号配置、稳定银行身份 | `payment_bank_account_tab` | 配置版不可覆盖；银行事件按 `account_fingerprint` 去重，不按配置行主键去重 |
| 资金单据及其冻结审批/执行摘要 | `payment_transaction_tab` | 按交易类型执行封闭生命周期；提交后改动另建单据，不覆盖原审批和回执 |
| 分配及可用/占用物化值 | `payment_fund_allocation_tab` | 原始毛额归属不因付款改变；金额修改须先合法撤销并新建 |
| 银行事实、三桶迁移、服务费结算事件 | `payment_fund_flow_tab` | 追加写；金额始终为正数、CNY；事件12从桶2可用余额转列，不伪造银行扣款 |
| 对账差异 | `payment_reconcile_difference_tab` | 差异本身不改余额；关闭前需处置证据和独立复核 |
| 资金控制账户、凭证、分录 | `account_tab`, `account_voucher_tab`, `account_ledger_entry_tab` | 余额投影、资金事件及借贷平衡凭证在一个本地事务中原子提交 |

只有三个货款资金位置：1受限、2可用、3付款锁额。事件8/9/10/11都不是第四个货款桶；
新服务费事件12只从桶2扣减可用余额并转列B服务费，不改变A合同应付。

## MySQL 本地事务轮廓

应用事务使用 `READ COMMITTED`。所有业务写先按原请求键查重，再锁交易根；同一实收
相关操作随后依次锁稳定银行身份、资金流水、分配/事务单据、资金控制账户（按账户号
稳定排序）和凭证来源键。获得根锁后，对参与计算的子集合使用 `FOR UPDATE` 当前读，
不可依赖根锁前建立的一致性读快照。事务中只做本地 SQL；银行、对象存储及杀毒扫描 I/O
都在事务外。确认写入后资金事件、物化投影和凭证/分录同一次 `COMMIT`；任何失败全部
`ROLLBACK`，并且不得消费确认或释放锁额。

### N11 — 合并实收与未匹配款

先用已核验、有效的收款账户配置和可验证银行来源核对稳定身份/银行事件键。原键同文
回放首次冻结结果，异文拒绝；新真实入账追加 `event_type=1`，`bucket_from=NULL`、
`bucket_to=1`，并为该来源记账。无法匹配交易的来款仍留在受限桶；不得伪造交易分配或
将其作为可支付余额。未接银行时不得插入银行成功事件。

### N12 — 分配及独立复核

事务内先查原分配请求，再锁交易根及实收流水；核对批准交易快照、批准商品/金额、稳定
银行账户身份及该实收累计有效分配。仅在毛额分配不超真实入账且范围匹配时追加待复核
分配；独立复核通过后将状态原子更新为有效。拒绝或超额时回滚，保留原流水及历史审查
记录，不生成余额。

### N13 — INVOICE申报

INVOICE 单据（类型1）保存B向D申报的发票版本、交易批准版及来源分配范围。补正以新
单/修订引用原记录，不覆盖提交版。INVOICE申报、补件、改版及重复提交均不触发服务费
结算；本节点不生成服务费账单或银行收款事件。

固定CNY 300服务费由D承担，只有贸易核验通过、国内人民币可用余额已确认、D授权齐备，
且该交易首次获批分账时，才按 `trade_number + agency_service_fee` 幂等追加事件12，
从桶2一次性结算。重复分账不重复扣费；余额不足或缺少授权时不扣费并阻断本次分账。

### N14 — 独立贸易审核及可用释放

贸易核验是范围/金额及证据审核，不等同银行可用。独立审核需检查确切交易快照、INVOICE
版次、分配及原实收、官方/合同证据、当时银行可用依据。实际银行可用证据齐备后，才按
受理范围追加 `event_type=3`，从桶1迁移至桶2；同事务更新 allocation `released_amount`
并记录账务分录。银行未接入或可用性无法确认时保持受限，即使审核意见通过也不得释放；
服务费仍须等首次获批分账时才从已核验可用余额结算。

### N15 — 结算、出口前预付与出口后付款依据

结算单（类型4）明确按有效分配/核验金额计算A合同应付、已付、锁额及授权扣款，并独立审批；
首次获批分账时服务费单独从D已核验可用余额结算，不得作为A合同应付扣项。预付款分支必须有真实已核验可用资金、适用批准交易/合同及
独立批准，不得以受限款、预计收款、授信、透支或B垫资填补缺口。出口后分支另核实
对应出口证据及结算条件。条件不足或金额来源不一致即拒绝审批。

### N16 — 付款审批、锁额、执行未知与到账

货款付款单（类型5）仅独立审批后可执行。短事务先锁稳定银行身份和所有相关有效分配/
桶投影，复核可用额、付款范围和受益方账户配置，再追加 `event_type=4`（桶2→桶3）并
同事务写凭证、分录及批准快照。只有提交成功后，事务外才调用银行；网络超时或结果不
明时将事务标为执行中/未知，锁额继续留在桶3。

未知执行只能按原付款单号及原幂等键向银行查单；不得重新发起新请求或新单。真实银行
明确扣款后追加 `event_type=2`（桶3→外部）并完成对应账务；银行明确失败且确认未扣款
时才追加 `event_type=5`（桶3→桶2）释放锁额。扣款不等于A已到账：A到账确认需独立
匹配银行/收款证据及付款双方信息。实际银行费用另按真实扣款证据追加事件11，保持桶
字段为空，不能将手续费当作A收款或货款扣减。

### N17 — 差异处置与恢复

重复/金额/执行状态/缺失一侧等事实进入差异单；缺证据使用NULL，不插入占位流水或虚构
零额。处理人补充原始证据后由独立复核人确认，必要资金调整追加新事件并生成对应凭证；
不得直接改余额、覆盖原交易或删除旧事件。未决差异可能影响的交易/分配/付款范围保持
门禁；明确结论后重算投影、核对凭证平衡，再恢复相关操作。

## 验证与范围

`assertions.sql` 用于检查服务费是否按交易重复、资金桶/账务是否有未勾稽投影等告警候选；
这些查询不是应用门禁或生产handler。`infra/local/verify-step-five.py` 只在最终共享DDL
稳定后，将本步骤使用的真实核心表复制到每次随机 `verify_step_five_<hex>` 库；验证结果
和DDL SHA-256 写入`--output`显式指定的JSON路径，不自动生成过程报告。银行/官方通道未接入时只验证
缺证据阻断、受限/锁额保持、原号查单模型和明确拒绝，不制造银行成功记录。
