# 方案验证中间件环境说明

面向ToB最多300单/日、持续2年、每单原件≤5MB/单文件约200KB及30次请求的硬件规划，见[自建机房两年资源规划](自建机房两年资源规划.md)及[主方案资源Tab](../交付成果/代理出口业务流程图.html#resources)。资源内分最小/适中/富裕三个预算Tab，当前8台方案属富裕档；各档均MySQL一主一从并另配独立备份，列出配置理由与风险，不含报价、不承诺全栈HA，也不代表本机组件已生产化。

本文件记录已部署的**本机开发验证环境**，供领域设计、步骤一/二时序图及后续应用实现验证使用。部署与验收基线为2026-10-25；服务状态、数据及凭据可能变化，验证前应重新检查。组件可用不代表业务流程、电子签署、资金控制或生产合规已实现。

八步骤的最终用例、接口和业务边界见各步骤的系统用例规约；数据库使用方式见[领域DDL指南](sql/domain/README.md)。原业务库未迁移，外部成功及正常结案端到端仍未验证。过程报告不作为交付物保留，复验结果由调用者显式指定保存位置，建议使用仓库外的临时目录。

## 1. 组件及接入入口

环境为macOS＋Docker CLI/Compose＋Colima，Docker context为 `colima`，VM配置2核、4GB内存、30GB磁盘。所有发布端口仅监听 `127.0.0.1`；MySQL与Colima注册为当前用户登录后自启，容器配置 `restart: unless-stopped`，**不是无人登录即启动**。

## 2. 与业务方案的验证对应

| 方案环节 | 可直接使用的依赖 | 已具备的基础设施验证 | 仍需应用实现或外部接入 |

| 首次建档、重复提交、边界快照、账务写入 | 业务MySQL | 45表/666列、组合唯一键、码值/金额约束、追加写保护；验收写入回滚 | 鉴权、确认消费、同键异文判断、锁序、跨表原子性、HMAC、借贷平衡及业务状态转换 |
| 单号预留与重入 | 业务MySQL | 可提供本地事务和唯一约束 | 编号计数/归属预留等基础设施表与取号模块尚未实现；不可仅靠自增id充当业务号 |

| 文件/操作回执/签署证据留存 | RustFS证据桶 | Object Lock能力、治理保留及禁止删除/越权绕过验证 | 逐对象批准保留策略、签名验证、授权链、可信时间、长期可验证证据和正式保全 |
| 定时恢复、重试与跑批 | XXL-JOB＋调度MySQL | 管理后台、登录及持久化基础就绪 | Java执行器/handler、任务配置、业务幂等、租约/栅栏、预算与未知结果核实；不能代替单体内恢复模块 |
| 运行状态、故障发现与排查 | Prometheus＋Blackbox＋Alertmanager＋Grafana | 真实抓取、探测、告警路由及数据源接通 | 业务指标、业务故障规则、真实外部通知、值守及处置流程 |
| 技术执行日志检索 | Docker日志代理→Alloy→Loki→Grafana | 真实日志采集、标签查询及合成字段脱敏验证 | 应用源头脱敏、trace_id关联、领域审计与审计留存策略 |

## 3. 文件存储及证据验证规则

S3 region为 `us-east-1`，使用path-style寻址。桶均私有并开启版本管理：

| 桶名 | 用途 | 应用权限/留存 |
|---|---|---|
| `export-trade-staging` | 临时上传原字节 | 应用可读写及清理暂存版本 |
| `export-trade-files` | 正式文件 | 应用禁止删除版本；开启Object Lock能力 |
| `export-trade-evidence` | 签署件、确认/受理回执及证据包 | 应用禁止删除版本、绕过治理保留；开启Object Lock能力 |

写入使用稳定键及 `If-None-Match: *`，保存真实VersionId、SHA-256及长度；引用确切版本而非latest或仅存路径。**版本管理本身不阻止同键写新版本**，必须配合应用条件写及确定版本引用。启用Object Lock不代表对象已锁定；当前未默认指定法定保留期，验收覆盖GOVERNANCE保留。管理员可显式绕过治理锁，不等同不可绕过的生产保全。

ClamAV流/单文件上限25MiB、解压扫描总量100MiB、递归16层、文件数10000，超限启用告警。未知、超时、病毒库过旧、拒绝或扫描不可用必须阻断文件确认；不能把扫描失败当通过。病毒库自动更新并持久保存，具体验证脚本要求签名库不超过7天；这只是本机检查门槛，不替代生产策略。

## 4. 监控、日志与调度验证入口

Prometheus当前有10个抓取目标：六个组件指标目标（Prometheus、Alertmanager、Grafana、Loki、Alloy、Blackbox）及四个服务探测目标（RustFS健康页、XXL-JOB登录页、ClamAV端口、调度数据库端口）。可在Prometheus或Grafana Explore使用：

```promql
up
probe_success
```

Grafana Explore切换Loki后可查询：

```logql
{environment="local",service="xxl-job"}
{environment="local",service="antivirus"} |= "ERROR"
```

日志带 `service`、`container`、`environment` 标签。脱敏规则仅辅助识别部分password/secret/token等字段，不能保证覆盖全部格式或个人信息；禁止应用输出真实密钥、完整身份/账号和合同正文。

Prometheus规则覆盖抓取失败、基础服务探测失败和日志投递丢弃，告警进入Alertmanager本机UI。指标保留15天/最多2GB（先达到者），Loki保留7天，容器stdout/stderr轮转10MB×3；调度日志配置保留7天。上述期限都是开发运维配置，**不是审计或法律证据保留期**。

XXL-JOB初始化去除官方示例任务、执行器分组和默认密码，仅保留必要调度锁及随机密码管理员。后续验证应注册专用测试执行器并使用无副作用handler，不直接创建付款、退款、签约等任务；任务重试仍须沿用原业务键并由所属领域授权。

## 5. 凭据、持久化与启动

凭据位于 `~/Library/ExportTradeLocal/`（目录0700、私有文件0600）；**文档不记录密码、token、S3密钥或数据库连接密文**。

| 文件 | 使用方 |
|---|---|
| `client.cnf` / `root-client.cnf` | 业务MySQL应用连接 / 私有socket管理连接 |
| `s3-client.json` | 受限S3应用连接 |
| `rustfs.env` | RustFS管理员，不能下发前端 |
| `observability-credentials.json` | Grafana与XXL-JOB管理员、调度token及调度数据库凭据 |

Grafana、XXL-JOB用户名均为 `admin`，使用各自随机密码；执行器将来须与调度后台配置一致的access token。运行容器环境、Docker socket和管理员凭据属于高权限管理信息，不对非可信用户开放。

MySQL数据保存在私有目录 `mysql-data/`；S3、病毒库、监控数据、日志、调度数据库及采集位置均有独立Docker命名卷。**不执行 `down -v`、volume prune或删除Colima VM**；本机卷不等同备份、高可用或灾难恢复。详细安装、卷名、停止操作及配置来源见[基础设施操作手册](../infra/local/README.md)；业务DDL选择见[领域MySQL说明](sql/domain/README.md)。

从仓库根目录恢复现有完整容器环境：

```sh
colima start
node infra/local/setup-observability.cjs
docker --context colima ps
```

不需重新初始化MySQL或重新导入DDL；已有实例禁止删除重建。若业务MySQL停止，使用已注册LaunchAgent：

```sh
launchctl kickstart "gui/$(id -u)/com.export-trade.mysql"
mysql --defaults-file="$HOME/Library/ExportTradeLocal/client.cnf"
```

## 7. 步骤一、二组合验证

`infra/local/verify-step-flows.py`使用本环境的MySQL、RustFS及ClamAV，而不是仅检查端口或静态JSON。每次创建随机命名的`verify_steps_<随机值>`独立库，复制当前七张交易/合同/文件核心表DDL及相应追加保护，再创建**验证专用最小中间件表**，不向`export_trade`添加任务表、测试数据或权限。

```sh
"$HOME/Library/ExportTradeLocal/s3-venv/bin/python" -m pip install -r infra/local/requirements-validation.txt
PYTHONDONTWRITEBYTECODE=1 "$HOME/Library/ExportTradeLocal/s3-venv/bin/python" \
  infra/local/verify-step-flows.py --output /tmp/export-trade-step-one-two-result.json
```

步骤三备货与物流采用相同环境，单独创建随机隔离库。只验证缺外部合同/正式放行/签收证据阻断，不伪造外部成功。

```bash
"$HOME/Library/ExportTradeLocal/s3-venv/bin/python" \
  infra/local/verify-step-three.py --output /tmp/export-trade-step-three-result.json
```

命令会使用私有MySQL管理连接创建新验证库、在私有目录保存该次随机测试HMAC密钥、在既有三桶中读写该次随机前缀对象并仅清理这些确切版本；验证库及脱敏报告保留，不自动删除历史验证库，不修改原步骤一演示库。测试行的对象引用在清理后不再可读取，不能当可复用业务样本。需要本文件已有boto3环境，额外驱动仅安装到同一私有venv。

测试范围包括并发取号/重入、部分写入回滚/确认消费、原受理回放、陈旧版并发、真实扫描及摘要拒绝、S3写成功后进程中断/新进程恢复、交易退回重送/更正快照、合同补正/审查/未知签署门禁。它是**测试驱动的方案验证，不是生产后端**；自动扫描/退避、真实认证、电子签/法定主体/官方授权、HTTP服务及XXL-JOB执行器仍未实现。恢复测试强制过期测试租约，并手动启动独立worker，不宣称调度器已经接管恢复。具体通过项和未验证项以本次执行输出为准。
