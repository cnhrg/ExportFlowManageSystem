# 步骤五：收款、结算与付款（N11–N17）

> 设计与离线验证规范，不是生产REST/RPC handler、真实IAM、银行接入或自动执行器。
> 本步骤使用一个模块化单体、对外/对内两类受众入口；不拆微服务，不实现授信、垫资、
> 透支或换汇。共同领域表与字段以`交付成果/assets/domain-model.js`和生成的
> `doc/sql/domain/schema.sql`为准，本步骤不增重复资金表。

## 1. 参与方、边界与编号

业务角色按批准交易快照确定：A为中国供应商、B为出口代理、C为实际收货人、D为付款方；
E为国际物流公司，F为出口报关代理。B收D货款；D承担的固定服务费在首次获批分账时从D可用余额结算，A货款仍按合同应付核算。
操作人员（经办、审核、审批、差异处理、复核）是身份与访问控制域中的不同人员，不是
新的交易业务主体。收款A的实际到账、银行扣款、服务费入账、银行手续费和记账凭证为
独立事实，不能由操作人声明、内部审批或付款成功状态代替。

本步骤的七个用例是：核实银行来款及未匹配金额；分配来款并独立复核；提交或补正商业发票申报且不触发服务费；
核验贸易资料并释放银行已确认可用的货款；试算并审批预付款或出口后付款结算单；
审批付款、锁定金额并确认供应商到账；处理资金差异并独立复核。
分别对应N11至N17，每项均有业务黑盒图和数据库、中间件实现图：
[逐项目录](examples/step5/README.md)。

## 2. 受众、头部、响应与重入

`ExternalFundsService`服务本方供应商/收款方视图；`InternalFundsOperationsService`
服务内部资金经办、独立审核/审批和差异复核。两者是同一单体的授权入口，不是两个
服务。外部资源必须按当前主体过滤；内部凭证不能给外部调用复用。

- 所有POST须有`Authorization`、`Idempotency-Key`、`X-Confirmation-Id`；更新须有强
  `If-Match`。确认绑定认证主体、受众、方法/路径、原键、标签和完整类型化请求正文。
- GET返回`200`、`Cache-Control: no-store`、强`ETag`及`response_body: "resource"`。
  POST返回`201`、同样的缓存/ETag头及`Location`；请求响应不确定时只用原方法、路径、
  原键、正文、标签和确认回执恢复。异文重用原键返回409，不另建资金单。
- JSON严格封闭；不接受未知字段、重复字段、指数金额、隐式舍入、浮点金额和非CNY。
  金额以字符串承载`DECIMAL(20,2)`，正数、固定两位，内部定点计算；未发生金额/证据
  使用缺省或NULL，不能伪造0或空银行流水。
- 文件先经共用上传任务保存暂存对象，事务外读取准确`VersionId`、校验长度/SHA-256并
  扫描同一字节；只提交不可变文件引用。S3/ClamAV/银行均不得持有业务数据库锁。

一致：读取客户端/服务端5,000/4,000ms；写入10,000/8,000ms。客户端取消或deadline

## 3. 资金状态、码表和实体映射

货款只有三个桶：1受限、2可用、3付款锁额。资金事件严格沿共享码表1–12：
1`bank_credit` NULL→1（真实银行实收）；2`bank_debit` 3→NULL（真实银行扣款）；
3`release` 1→2；4`lock` 2→3；5`unlock` 3→2（仅明确未扣款失败/取消）；
6`restrict` 2→1；7`reversal`按原事件反向并限制原金额；8`service_fee_billed`、
9`service_fee_voided`、10`agency_fee_bank_credit`均为历史兼容事件，新业务不再生成；
11`bank_fee_debit`为真实银行费用；12`agency_service_fee_settled`为D承担的固定300元
从桶2可用余额转列B服务费。事件12要求贸易核验、可用余额及D授权证据；不得伪造银行
扣款或创建第四资金桶。

本步只投影共享实体：账号配置`payment_bank_account_tab`；INVOICE、核验、服务费、
结算、付款及退款`payment_transaction_tab`；来款分配`payment_fund_allocation_tab`；
银行/内部资金事实`payment_fund_flow_tab`；差异`payment_reconcile_difference_tab`；
余额账户、凭证、分录分别为`account_tab`、`account_voucher_tab`、
`account_ledger_entry_tab`。凭证按来源号/记账阶段回查，不在流水上回填凭证号。详见
[资金实体事务约束](sql/step5/README.md)与只读核对候选
[assertions.sql](sql/step5/assertions.sql)。

## 4. N11–N17关键门禁与事务

### N11–N12：实收、受限、分配

同一真实账号按`account_fingerprint + bank_event_key`跨配置版本去重；只有银行确认实际
到账才追加event 1并记账。无银行接口时，`CreateBankReceiptEvidence`仅是内部待核证据，
不得冒称银行回调。未匹配金额留受限，不能生成虚构交易/分配。分配锁定trade根、批准
快照、稳定银行身份、实收与按序`FOR UPDATE`的分配行，当前读后以定点金额验证
`实收毛额 = 有效分配 + 未匹配`。分配创建与复核分离；待复核不提供付款额度。

### N13：INVOICE申报

INVOICE是独立单据，补正关联旧版且新建不可变提交，不表示银行已入账或可用。申报、
补件、改版及重复提交均不触发服务费结算，也不生成独立服务费账单或银行收款事实。
固定CNY 300服务费由D承担，仅在贸易核验通过、国内人民币可用余额已确认、D授权齐备，
且该交易首次获批分账时结算。服务费事件`agency_service_fee_settled`（event 12）按
`trade_number + agency_service_fee`幂等，从桶2可用余额转列B服务费；不是银行扣款，
不新增货款桶，也不减少A合同应付。余额不足或缺授权时不得扣费或完成分账；重复分账
不重复结算。旧event 8/9/10保留为历史兼容码，新业务不再生成；银行实际费用仍按真实
凭证记event 11。

### N14：贸易核验与实际可用/部分释放

贸易核验复核INVOICE、批准交易、有效分配、范围、合同/正式证据。内部审核通过不是
银行可用证明。仅真实银行可用证据与同一分配/范围金额匹配时，追加event 3并部分/全额
从受限转可用；资金事件、`released_amount`、相关控制账户投影、凭证及分录同一MySQL
短事务原子提交。证据缺失时拒绝并保持受限。

### N15：结算与两种付款分支

结算列示应付、已付、未付、经授权第三方扣款及净额；300服务费不冲减货款。付款要求码
1–14按域内闭合枚举，不接受自由码/空证据代替豁免：

| 码 | 付款证据 |
| ---: | --- |
| 1 | A–B协议 |
| 2 | B指定/认可F |
| 3 | A委任同一F |
| 4 | A–F协议 |
| 5 | 有效报关电子委托 |
| 6 | 金额、CNY、批次、独立审批人 |
| 7 | A书面批准最终草稿 |
| 8 | 正式申报件列B为境内发货人 |
| 9 | B已收到申报件 |
| 10 | 正式放行证明 |
| 11 | D实收匹配（非汇款水单） |
| 12 | 适用银行书面条件 |
| 13 | 批准结算净额 |
| 14 | 费用承担/收费适用授权 |

预付款至少满足1–6和11–14及本交易适用的其余协议；只使用真实已核实可用人民币资金。
出口后付款至少满足1、3、5–14及其它必需协议/物流/报关条件，须核实正式附件、B已
收到附件、放行及D实收匹配。公共协议只在主体、用途和期间都匹配时可作证据。缺任一
必要项则阻断；不使用垫资、授信、透支或预期入账。

### N16：独立审批、锁额、未知恢复及A到账

付款批准前复核交易/合同版本、预付款或出口后证据、受益人银行配置版、有效资金分配、
未决差异及可用余额。按固定锁序短事务追加event 4（2→3）、更新占用投影、冻结付款
执行快照并写平衡凭证/分录，之后才可事务外调用银行。银行未知以`execution_status=3`
保留锁额，查询只使用原`transaction_number`及原键；不得发新单。确认真实扣款才event
2（3→NULL），确认未扣款的明确失败/取消才event 5（3→2）。银行扣款不表示收款方A
已到账；A到账确认是单独的收款方证据和核对事实。

### N17：差异与恢复

差异类型为缺失、重复、金额、状态。未知一侧为空；只有证据确认缺失才允许报告0。
差异处置和独立复核分别留痕；关闭前勾稽银行/资金/账务事实，补账/调账追加新资金事件
和凭证，禁止改旧流水、直接改账户余额或删除历史。未决差异维持相关范围门禁，不能
释放未知付款锁额。

## 5. 锁序、事务与文件/银行边界

写请求`BEGIN READ COMMITTED`后**先按当前身份、方法、路径、原键及摘要查幂等**；同文
返回原受理结果，异文409。新写按交易根→稳定银行账号身份→实收流水/INVOICE/结算/
付款单→分配行（业务号排序）→资金控制账户（`account_number`排序）→凭证/分录来源键
固定锁序。根锁之后对子表查询用`SELECT ... FOR UPDATE`当前读，避免快照读漏掉并发
事务刚提交的分配/占用。资金事件、投影、凭证/分录及确认消费同一COMMIT，失败整体
ROLLBACK。事务预算2秒、锁等待1秒；争用重试先重新开事务查原键。

S3、ClamAV、银行查询/扣款/到账证据处理在事务外。文件任务使用持久任务、确切版本和
原键恢复；银行执行未知时持锁，原号查单，禁止盲重发或超时解锁。没有真实银行适配器
时只展示“未提交/待核/未知”和缺证据错误；不生成虚构`bank_credit`、可用释放、扣款、
费用或A到账成功。

## 6. 稳定错误与恢复

业务错误通过HTTP响应及`trade.filing.v1.RpcFailure`表达；RPC非成功返回gRPC status，
不返回成功resource形状。可恢复错误也不代表重做业务；POST必须原键原文查询/重试。

| 稳定业务码 | HTTP / gRPC | 可重试 | 处置 |
| --- | --- | --- | --- |
| `INVALID_INPUT / UNKNOWN_FIELD / AMOUNT_FORMAT_INVALID / CURRENCY_NOT_SUPPORTED / IDEMPOTENCY_CONFLICT` | 400或409 / INVALID_ARGUMENT或ALREADY_EXISTS | 否 | 修复字段；异文键停止使用 |
| `FORBIDDEN / NOT_FOUND` | 403/404 / PERMISSION_DENIED/NOT_FOUND | 否 | 使用正确主体/资源；不通过猜测存在性绕过授权 |
| `IF_MATCH_REQUIRED / REVISION_CONFLICT` | 428/412 / FAILED_PRECONDITION | 否 | GET当前资源；重新人工确认新正文后用新键 |
| `RECEIPT_UNMATCHED / ALLOCATION_EXCEEDED / ACCOUNTING_UNBALANCED` | 409 / FAILED_PRECONDITION | 否 | 读取原流水/分配/凭证并处置；不另造资金 |
| `FUND_EVIDENCE_MISSING / BANK_AVAILABILITY_EVIDENCE_REQUIRED / BANK_EVIDENCE_REQUIRED / PAYEE_RECEIPT_UNVERIFIED` | 422 / FAILED_PRECONDITION | 否 | 补充真实银行证据；维持原桶/锁额 |
| `PAYMENT_GATE_INCOMPLETE / BENEFICIARY_UNVERIFIED / CONTRACT_OR_EXPORT_EVIDENCE_MISSING` | 422 / FAILED_PRECONDITION | 否 | 按预付/出口后门禁补齐及复核 |
| `SERVICE_FEE_ALREADY_SETTLED` | 409 / ALREADY_EXISTS | 否 | GET原结算记录；不重复结算 |
| `DIFFERENCE_OPEN / LEDGER_EVENT_CONFLICT` | 409 / FAILED_PRECONDITION | 否 | 原差异处置、独立复核后再试 |
| `DEPENDENCY_UNAVAILABLE / COMMIT_OUTCOME_UNKNOWN / EXECUTION_OUTCOME_UNKNOWN` | 503 / UNAVAILABLE | 有条件 | 主库按原请求/付款号恢复；未知时绝不新号重付/解锁 |
| `DEADLINE_EXCEEDED / CLIENT_CANCELLED` | 504/无HTTP / DEADLINE_EXCEEDED/CANCELLED | 视结果 | 客户端超时不是事务失败；先按原键查询 |
| `INTERNAL_ERROR` | 500 / INTERNAL | 否 | 告警并人工定位，不自动业务重提 |

## 7. 服务费流程文字的修订建议

所有“每张invoice各收300”“INVOICE申报触发收费”或“从A应付扣300”的旧流程说明，
应统一为：固定CNY 300服务费由D承担，只有首次获批分账时才从D已核验可用余额结算，
以`trade_number + agency_service_fee`防止重复。INVOICE申报、补件、改版不触发收费；
D授权、贸易核验和可用余额不足时不扣费；服务费结算从可用余额转列，不减少A合同应付。
银行实际费用按真实凭证另行勾稽。
